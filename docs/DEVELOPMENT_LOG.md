## 2026-08-18 · v1.0.2 日志性能与导出

### 问题复现

抓包日志文件增长到数百 KB 后，点击“抓包日志”需要约 1–2 秒才能进入；运行日志因为文件较小，进入速度明显更快。

### 根因分析

旧实现会在 UI 主线程从文件第一行读取到最后一行，并在字符串超过限制时反复删除头部内容。该过程同时包含磁盘读取、字符串移动和大型 TextView 排版。`onCreate` 后紧接着执行的 `onResume` 又触发一次刷新，因此抓包日志越大，阻塞越明显。

### 修复方案

- 读取任务移动到后台线程；
- 使用随机访问直接读取文件尾部；
- 预览上限调整为 220 KB；
- 完整内容改由导出功能读取；
- 删除重复生命周期刷新；
- 重构顶部布局以容纳导出、刷新和清空按钮。

### 验证结果

- release 构建成功；
- APK 覆盖安装成功；
- 真机抓包日志页面显示耗时约 523 ms；
- 标题与按钮无挤压或换行；
- 系统文件选择器成功创建导出文件；
- 导出的文件包含完整抓包日志；
- APK v1/v2 签名验证通过。
